Формат WebSocket-кадра

Заголовок кадра начинается с двух байтов.

1 Поле 2 Размер 3 Назначение 

1 FIN 2 1 бит 3 1 — последний фрагмент сообщения 
1 RSV1–RSV3 2 3 бита 3 Зарезервированы; обычно равны нулю 
1 Opcode 2 4 бита 3 Тип кадра: 0x1 текст, 0x2 бинарный, 0x8 Close, 0x9 Ping, 0xA Pong 
1 MASK 2 1 бит 3 Признак наличия ключа маскирования 
1 Payload Length 2 7 бит или расширенное поле 3 Длина данных 
1 Masking Key 2 0 или 4 байта 3 Ключ, если MASK=1 
1 Payload Data 2 переменная длина 3 Полезная нагрузка 


Зачем клиент маскирует данные

Клиент WebSocket обязан маскировать каждый кадр, отправляемый серверу.
Для каждого байта payload применяется XOR с одним из четырёх байтов ключа:

decoded[i] = masked[i] XOR masking_key[i % 4]

Маскирование не является шифрованием и не обеспечивает конфиденциальность.
Оно нужно для защиты инфраструктуры посредников от неоднозначной интерпретации
данных клиентского потока. Серверные кадры, отправляемые клиенту, не маскируются.

 Управляющие кадры

- Close (0x8) — завершение WebSocket-соединения.
- Ping (0x9) — проверка доступности другой стороны.
- Pong (0xA) — ответ на Ping; payload должен совпадать с payload Ping.
